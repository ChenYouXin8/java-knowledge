# 工具链速查与面试题

> Maven · Git · IDEA 三者的横向对比、速查清单和面试高频题。

---

## 1️⃣ 对比表格

### 1-1 Maven 命令对应 IDEA 操作

| Maven 命令 | IDEA 操作 | 场景 |
|-----------|---------|------|
| mvn compile | IDEA 自动编译 / Ctrl+Shift+F9 | 编译检查错误 |
| mvn test | 运行测试类旁边绿色按钮 | 跑单元测试 |
| mvn package | Maven 面板 → Lifecycle → package | 打包 jar |
| mvn clean | Maven 面板 → Lifecycle → clean | 清理旧文件 |
| mvn dependency:tree | Maven 面板 → Dependencies | 查看/排查依赖 |
| mvn help:effective-pom | Maven 面板 → pom.xml 右键 → Show Effective POM | 看完整配置 |

### 1-2 Git 三棵树

| 区域 | 命令 | 说明 |
|------|------|------|
| 工作区（Working Tree） | git status | 你正在编辑的 |
| 暂存区（Staging） | git add / git reset | 准备提交的文件快照 |
| 仓库（Repository） | git commit | 已提交的版本历史 |

### 1-3 IDEA 与 VS Code 对比

| 维度 | IDEA | VS Code |
|------|------|---------|
| 定位 | Java 专业 IDE | 通用代码编辑器 |
| 智能提示 | 强（懂 Java 语义） | 一般（靠插件） |
| 重构 | 内置，强大 | 依赖插件 |
| 调试 | 功能完整 | 依赖插件 |
| 启动速度 | 慢（功能多） | 快 |
| 内存占用 | 高（~1GB） | 低（~200MB） |
| 价格 | 社区版免费/终极版收费 | 免费 |
| Java 项目 | **强烈推荐 IDEA** | 可用但不推荐 |
| 多语言 | 一般 | **强烈推荐** |

## 2️⃣ 速查清单

### Maven 速查

` powershell
# 常用命令
mvn clean compile                        # 清理+编译
mvn test                                 # 运行测试
mvn package -DskipTests                  # 打包（跳过测试）
mvn dependency:tree > tree.txt           # 导出依赖树
mvn dependency:analyze                   # 分析未使用/可传递依赖
mvn spring-boot:run                      # 运行 Spring Boot
mvn help:effective-pom > pom.xml         # 查看有效 POM
` 

### Git 速查

` powershell
# 日常流程
git status                               # 查看改动
git add .                                # 暂存所有
git commit -m "feat: xxx"               # 提交
git push origin main                     # 推送

# 解决冲突
git fetch origin                         # 拉取远程最新
git merge origin/main                     # 合并
# 手动解决 → git add → git commit → git push

# 紧急修复（hotfix）
git checkout -b hotfix/xxx main          # 从 main 创建热修分支
`

## ❓ 常见面试题

**Q1: Maven 的依赖传递是什么？**
> 如果 A 依赖 B，B 依赖 C，那么 A 会自动获得 C（传递依赖）。可以用 <optional>true</optional> 阻止传递，用 <exclusions> 排除某个传递依赖。依赖冲突时，Maven 用"最短路径优先"原则选择版本。

**Q2: Git 的 merge 和 rebase 区别？**
> git merge 保留真实分叉历史，适合协作分支。git rebase 把当前分支的提交"复制"到目标分支之后，历史变成一条直线，更干净。规则：**已经 push 到远程的分支不要 rebase**。

**Q3: Git 怎么撤销已经 push 的提交？**
> git revert HEAD（安全撤销，创建新提交来反向之前的改动）。或者 git reset --hard HEAD~n + git push --force（危险，改历史）。

**Q4: Maven 的 scope 有哪些？**
> compile（默认）、provided（编译时用，打包时不包含）、untime（运行/测试用）、	est（只在测试时有效）、system（不推荐）。

**Q5: Git 如何解决合并冲突？**
> 1. git pull 时报 CONFLICT；2. 搜索 <<<<<<< HEAD 标记；3. 手动保留想要的代码；4. git add；5. git commit。

**Q6: Maven 的聚合和继承是什么？**
> 聚合：父项目用 packaging=pom，管理多个子模块。继承：子 POM 的 <parent> 继承父 POM 的 <dependencyManagement> 版本管理。

**Q7: IDEA 里如何排查 Maven 依赖冲突？**
> Maven Helper 插件（pom.xml → Dependencies → 红色的是冲突）；或 mvn dependency:tree -Dverbose。

**Q8: Git 的 HEAD 是什么？**
> HEAD 是指向当前分支最新提交的指针。HEAD~1 = 父提交，HEAD~2 = 祖父提交。

## 🐛 踩坑记录

- **Maven 下载慢**：没配阿里云镜像；配好后删 .m2/repository 重下
- **git add . 误提交**：加了不该加的文件；提交前 git status 先看一眼
- **.gitignore 不生效**：文件已被 track 后再写 .gitignore 无效；需 git rm --cached filename
- **IDEA 编译版本不对**：pom.xml 设为 Java 17 但 IDEA SDK 是 21；保持一致
- **git commit 信息随便写**：用 Conventional Commits 格式
- **git push --force**：强推会覆盖远程历史；只在个人分支用
- **IDEA Lombok 插件**：装了依赖但没装插件会报红；装插件并启用 Annotation Processing
- **Maven 仓库路径中文**：.m2 放在中文路径下可能出问题
- **git reset --hard 丢失代码**：用前确认已提交或 stash
