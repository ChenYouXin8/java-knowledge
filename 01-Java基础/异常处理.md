## 1️⃣ 代码模板

### 1-1 try-catch-finally 标准模板

```java
// 模板1：基础捕获
try {
    int result = 10 / 0;
} catch (ArithmeticException e) {
    System.out.println("算术错误：" + e.getMessage());
} finally {
    System.out.println("总是执行");
}

// 模板2：多异常捕获（Java 7+）
try {
    int[] arr = {1, 2};
    arr[10] = 0;  // ArrayIndexOutOfBoundsException
} catch (ArithmeticException | NullPointerException e) {
    System.out.println("算术或空指针：" + e.getMessage());
} catch (Exception e) {
    System.out.println("其他异常：" + e.getMessage());
} finally {
    // 清理资源
}

// 模板3：finally 中 return 的坑
try {
    return 1;
} finally {
    System.out.println("finally 执行");
    return 2;  // ❌ 吞掉 try 的 return，最终返回 2
}
// 不要在 finally 里写 return！
```

### 1-2 try-with-resources 模板（推荐）

```java
// Java 7+：自动关闭资源
// 实现 AutoCloseable 接口的对象都可以

// 单资源
try (BufferedReader br = new BufferedReader(
        new FileReader("test.txt"))) {
    String line;
    while ((line = br.readLine()) != null) {
        System.out.println(line);
    }
} // 自动调用 br.close()

// 多资源（Java 9+ 可以省略变量声明）
try (var br = new BufferedReader(new FileReader("a.txt"));
     var bw = new BufferedWriter(new FileWriter("b.txt"))) {
    String line;
    while ((line = br.readLine()) != null) {
        bw.write(line);
        bw.newLine();
    }
}

// 常见实现 AutoCloseable 的类
try (Scanner sc = new Scanner(System.in)) {}
try (Socket socket = new Socket("localhost", 8080)) {}
try (Connection conn = DriverManager.getConnection(url, user, pwd)) {}
```

### 1-3 自定义异常模板

```java
// 模板1：业务异常基类
public class BusinessException extends RuntimeException {
    private final int code;

    public BusinessException(int code, String message) {
        super(message);
        this.code = code;
    }

    public int getCode() { return code; }
}

// 模板2：带异常的构造函数
public class BusinessException extends RuntimeException {
    private final int code;

    public BusinessException(int code, String message) {
        super(message);
        this.code = code;
    }

    public BusinessException(int code, String message, Throwable cause) {
        super(message, cause);  // 保留原始异常链
        this.code = code;
    }
}

// 使用
public User getUser(Long id) {
    if (id == null || id <= 0) {
        throw new BusinessException(400, "用户ID无效");
    }
    User user = userDao.findById(id);
    if (user == null) {
        throw new BusinessException(404, "用户不存在: " + id);
    }
    return user;
}
```

### 1-4 Spring 全局异常处理器模板

```java
@RestControllerAdvice
public class GlobalExceptionHandler {

    // 捕获业务异常
    @ExceptionHandler(BusinessException.class)
    public ApiResponse<Void> handleBusiness(BusinessException e) {
        log.warn("业务异常 code={} msg={}", e.getCode(), e.getMessage());
        return ApiResponse.fail(e.getCode(), e.getMessage());
    }

    // 捕获参数校验异常
    @ExceptionHandler(MethodArgumentNotValidException.class)
    public ApiResponse<Void> handleValid(MethodArgumentNotValidException e) {
        String msg = e.getBindingResult().getFieldErrors().stream()
            .map(err -> err.getField() + ": " + err.getDefaultMessage())
            .collect(Collectors.joining(", "));
        return ApiResponse.fail(400, msg);
    }

    // 捕获所有未知异常
    @ExceptionHandler(Exception.class)
    public ApiResponse<Void> handleAll(Exception e) {
        log.error("系统错误", e);
        return ApiResponse.fail(500, "系统繁忙，请稍后重试");
    }
}

// ApiResponse 统一返回体
public class ApiResponse<T> {
    private int code;
    private String message;
    private T data;

    public static <T> ApiResponse<T> success(T data) {
        ApiResponse<T> r = new ApiResponse<>();
        r.code = 200;
        r.message = "success";
        r.data = data;
        return r;
    }

    public static <T> ApiResponse<T> fail(int code, String msg) {
        ApiResponse<T> r = new ApiResponse<>();
        r.code = code;
        r.message = msg;
        return r;
    }
}
```

## 2️⃣ 对比表格

### 2-1 常见异常速查

| 异常类 | 触发场景 | 检查方式 |
|--------|---------|---------|
| `NullPointerException` | 空引用调用方法 | `obj != null` |
| `ArrayIndexOutOfBoundsException` | 数组下标越界 | 下标 < length |
| `StringIndexOutOfBoundsException` | 字符串下标越界 | `s.substring(i)` 中 i > length |
| `ArithmeticException` | 算术错误（如除以0） | 分母非零检查 |
| `ClassCastException` | 强制类型转换失败 | `instanceof` 先检查 |
| `IllegalArgumentException` | 参数不合法 | 方法入口校验 |
| `ConcurrentModificationException` | 迭代时修改集合 | 用迭代器 remove |
| `NumberFormatException` | 字符串转数字格式错 | `try Integer.parseInt()` |

### 2-2 Error vs Exception

| 维度 | Error | Exception |
|------|-------|-----------|
| 性质 | 系统级错误 | 程序级错误 |
| 处理 | 程序不应捕获 | 应该捕获并处理 |
| 示例 | OOM、StackOverflowError | NPE、IOException |
| 发生 | JVM 内部或硬件问题 | 业务逻辑问题 |
| 是否受检 | 非受检 | 有受检（checked）和非受检（unchecked） |

### 2-3 final / finally / finalize

| 关键字 | 作用 | 是否Java关键字 |
|--------|------|--------------|
| `final` | 修饰类（不可继承）、方法（不可重写）、变量（不可修改） | ✅ |
| `finally` | try-catch 清理块，必然执行 | ✅ |
| `finalize` | Object 方法，GC 前调用（已废弃） | ❌（方法名） |

### 2-4 throw vs throws

| 关键字 | 位置 | 作用 |
|--------|------|------|
| `throw` | 方法体内，抛出**一个**具体异常对象 | `throw new XxxException()` |
| `throws` | 方法签名，声明**可能抛出**的异常类型 | `public void foo() throws IOException` |

## 3️⃣ 图解结构

### 3-1 异常体系

```
Throwable
├── Error（系统级，程序无法处理）
│   ├── OutOfMemoryError（内存耗尽）
│   ├── StackOverflowError（栈溢出）
│   └── NoClassDefFoundError（类加载失败）
└── Exception（程序级，可处理）
    ├── IOException（受检，编译器强制处理）
    │   ├── FileNotFoundException
    │   └── SocketException
    ├── SQLException（受检）
    └── RuntimeException（非受检，运行时异常）
        ├── NullPointerException
        ├── ArrayIndexOutOfBoundsException
        ├── ArithmeticException
        ├── ClassCastException
        ├── IllegalArgumentException
        └── ConcurrentModificationException
```

## 4️⃣ 速查清单

### 4-1 异常处理最佳实践

```
✅ 推荐做法：
1. 能处理的异常才 catch，否则 throws
2. catch 先捕获具体异常，再捕获通用异常
3. 异常信息要详细：包含上下文
4. 不要吞异常：catch 块至少打印日志
5. 优先 try-with-resources
6. 受检异常无法处理时，往上抛
7. 用 BusinessException 统一业务异常

❌ 错误做法：
1. 空 catch 块：catch (Exception e) {}
2. 吞掉异常：catch (Exception e) { return; }
3. 用异常做流程控制：if-else 替代
4. catch 顺序错误：先 catch Exception 再 catch 具体异常
5. 不清理资源：不用 try-with-resources 或 finally
```

## ❓ 常见面试题

**Q1: final / finally / finalize 的区别？**
> 详见上方对比表格 2-3。

**Q2: throw 和 throws 的区别？**
> 详见上方对比表格 2-4。

**Q3: try-with-resources 的优势？**
> 自动调用 `close()`，即使异常发生也会关闭；代码更简洁；自动处理多个资源。

**Q4: 子类重写方法能抛出新异常吗？**
> 不能抛出比父类更宽泛的受检异常。可以不抛异常，或抛父类异常的子类/RuntimeException。

## 🐛 踩坑记录

- `catch` 顺序：先具体后通用
- `finally` 里有 `return` 会吞掉异常
- 子类重写不能抛比父类更宽的受检异常
- `try-with-resources` 中 `close()` 异常会被**抑制**，用 `e.getSuppressed()` 获取
- 空 catch 块是最坏的做法（至少打印日志）
