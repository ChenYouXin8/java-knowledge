# 泛型与注解

> 泛型：编译时类型安全检查 + 代码复用。注解：给代码打标签，框架大量使用。

---

## 1️⃣ 代码模板

### 1-1 泛型类 / 方法 / 接口模板

```java
// 泛型类模板
public class Box<T> {
    private T value;

    public T get() { return value; }
    public void set(T value) { this.value = value; }

    // 泛型方法模板
    public static <U> U copyIfNotNull(U item) {
        return item != null ? item : null;
    }
}

// 多类型参数
public class Pair<K, V> {
    private K key;
    private V value;

    public Pair(K key, V value) {
        this.key = key;
        this.value = value;
    }

    public K getKey() { return key; }
    public V getValue() { return value; }
}

// 泛型接口模板
public interface Converter<F, T> {
    T convert(F from);
}

public class StringToIntConverter implements Converter<String, Integer> {
    @Override
    public Integer convert(String from) {
        return Integer.parseInt(from);
    }
}
```

### 1-2 泛型边界模板

```java
// 上界：T 必须是 Number 或其子类
public class NumberBox<T extends Number> {
    private T value;

    public double toDouble() {
        return value.doubleValue();  // 可调用 Number 的方法
    }
}

NumberBox<Integer> nb = new NumberBox<>();  // ✅ Integer extends Number
// NumberBox<String> ns = new NumberBox<>();  // ❌ String 不是 Number

// 多个上界（用 & 连接）
public class DataProcessor<T extends Comparable & Serializable> {
    public void process(T data) {
        // T 既是 Comparable 又是 Serializable
        data.compareTo(data);
        // data 可被序列化
    }
}
```

### 1-3 PECS 原则模板

```java
// Producer Extends：只读，传入数据
public static double sumOfList(List<? extends Number> list) {
    double sum = 0;
    for (Number n : list) {  // ✅ 可以读，返回 Number
        sum += n.doubleValue();
    }
    // list.add(123);  // ❌ 不能写，编译器不知道具体类型
    return sum;
}

// Consumer Super：只写，输出数据
public static void addNumbers(List<? super Integer> list) {
    list.add(1);       // ✅ 可以写，Integer 是 Integer 或其父类
    list.add(2);
    // Integer n = list.get(0);  // ❌ 不能读，返回 Object
}

// 实际应用
List<Number> numList = new ArrayList<>();
List<Integer> intList = new ArrayList<>();

sumOfList(intList);   // List<Integer> → List<? extends Number>
addNumbers(numList);  // List<Number> → List<? super Integer>
```

### 1-4 注解定义模板

```java
// 定义注解
import java.lang.annotation.*;

// 元注解
@Retention(RetentionPolicy.RUNTIME)   // 保留到运行时（反射必需）
@Target(ElementType.METHOD)          // 只能用在方法上
@Documented                          // 加入 Javadoc
public @interface MyLog {
    String value() default "";        // 属性，默认空字符串
    int level() default 0;          // 默认 0
    String[] tags() default {};      // 数组属性
}

// 使用注解
public class UserService {
    @MyLog(value = "查询用户", level = 1, tags = {"read", "user"})
    public User getUser(Long id) {
        return userDao.findById(id);
    }

    @MyLog("新增用户")
    public void addUser(User user) {
        userDao.save(user);
    }
}

// 反射读取注解
public class LogAspect {
    public static void main(String[] args) throws Exception {
        Method method = UserService.class.getMethod("getUser", Long.class);
        MyLog log = method.getAnnotation(MyLog.class);
        if (log != null) {
            System.out.println("日志记录: " + log.value());
            System.out.println("级别: " + log.level());
            System.out.println("标签: " + Arrays.toString(log.tags()));
        }
    }
}
```

### 1-5 注解属性规则速记

```java
// ✅ 合法的注解属性类型
@MyAnnotation(
    str = "hello",          // String
    val = 123,             // 基本类型
    clazz = String.class,  // Class
    color = Color.RED,     // 枚举
    annotation = @OtherAnnotation("x"),  // 注解类型
    arr = {"a", "b"}       // 数组
)

// ❌ 不合法的属性类型
// 泛型、Class<? extends T>、Throwable 等不允许
```

## 2️⃣ 对比表格

### 2-1 泛型擦除后的类型

| 泛型写法 | 擦除后类型 | 说明 |
|---------|-----------|------|
| `<T>` | `Object` | 无边界时 |
| `<T extends Number>` | `Number` | 有上界时，擦除为上界 |
| `<T super Integer>` | `Object` | 下界只用于编译检查，不参与擦除 |

### 2-2 `List<Object>` / `List<?>` / `List<T>` 对比

| 类型 | 能 add 吗 | 能 get 吗 | 典型场景 |
|------|---------|---------|---------|
| `List<Object>` | `list.add(new Dog())` ✅ | `Object o = list.get(0)` | 需要放入任意类型 |
| `List<?>` | ❌ | `Object o = list.get(0)` | 只读，只遍历 |
| `List<String>` | `list.add("hi")` ✅ | `String s = list.get(0)` | 特定类型 |

### 2-3 注解保留策略

| 策略 | 说明 | 典型场景 |
|------|------|---------|
| `SOURCE` | 仅源码，编译后丢弃 | `@Override`、`@SuppressWarnings` |
| `CLASS` | 编译时保留，运行时丢弃 | 编译期检查（少用） |
| `RUNTIME` | 运行时常驻，可反射读取 | `@Controller`、`@Autowired` |

### 2-4 注解 vs 注释

| 维度 | 注解（Annotation） | 注释（Comment） |
|------|------------------|----------------|
| 本质 | 特殊接口（`extends Annotation`） | 纯文本 |
| 编译器处理 | 编译器/运行时可识别 | 完全忽略 |
| 反射读取 | ✅ 可通过反射读取 | ❌ 不可以 |
| 框架支持 | Spring/MyBatis 大量使用 | 无关框架 |

## 3️⃣ 图解结构

### 3-1 类型擦除过程

```
源代码：
public class Box<T> {
    private T value;
    public T get() { return value; }
    public void set(T value) { this.value = value; }
}

编译后（类型擦除）：
public class Box {
    private Object value;          // T → Object
    public Object get() { return value; }
    public void set(Object value) { this.value = value; }
}

调用处自动插入类型转换：
Box<String> box = new Box<>();
String s = box.get();  → 编译后变成 →  (String) box.get();
```

### 3-2 泛型边界擦除

```
<T extends Number> 擦除后：
public class NumberBox {
    private Number value;    // T → Number（不是 Object！）
    public Number get() { return value; }
    public void set(Number value) { this.value = value; }
}
```

### 3-3 注解处理流程

```
源码阶段：
  @MyLog("查询用户")
  public User getUser(Long id) { ... }

编译阶段（Retention=SOURCE 时丢弃）：
  编译器检查注解是否存在、参数是否正确

编译阶段（Retention=CLASS 时保留）：
  .class 文件中包含注解元数据

运行阶段（Retention=RUNTIME 时存在）：
  反射读取 → Method.getAnnotation(MyLog.class)
             → 得到注解对象 → 读取属性值
             → 执行业务逻辑（日志、AOP 等）
```

## 4️⃣ 速查清单

### 4-1 Java 内置注解速查

| 注解 | 作用 |
|------|------|
| `@Override` | 编译时检查是否重写父类方法 |
| `@Deprecated` | 标记已过时，编译器警告 |
| `@SuppressWarnings("unchecked")` | 压制泛型未检查警告 |
| `@FunctionalInterface` | 标记函数式接口，检查是否符合 |
| `@SafeVarargs` | 压制泛型可变参数警告 |
| `@Retention(RUNTIME/CLASS/SOURCE)` | 注解保留策略 |
| `@Target(...)` | 注解使用位置 |

### 4-2 常见注解使用场景

| 注解 | 来源 | 使用场景 |
|------|------|---------|
| `@Autowired` | Spring | 依赖注入 |
| `@Service` | Spring | 标记为服务层 Bean |
| `@Controller` | Spring | 标记为控制器 |
| `@GetMapping` | Spring MVC | GET 请求映射 |
| `@Transactional` | Spring | 声明事务 |
| `@Override` | JDK | 方法重写检查 |
| `@FunctionalInterface` | JDK | 函数式接口检查 |

## ❓ 常见面试题

**Q1: `List<Object>` 和 `List<?>` 的区别？**
> 详见上方对比表格 2-2。

**Q2: `static` 方法可以用泛型吗？**
> 不能直接用类的泛型 `<T>`，必须声明自己的泛型：`<T> T foo(T t)`。

**Q3: 泛型擦除后，约束还存在吗？**
> 存在。编译器在边界处插入类型转换代码，`set(T value)` 擦除后变成 `set(Object value)`，但调用 `box.set("abc")` 时编译器会自动插入强转。

**Q4: `@interface` 是类吗？**
> 是。编译后变成 `extends Annotation`，注解本质是一个**特殊接口**。

**Q5: PECS 怎么记？**
> Producer（生产者）用 `extends`（只读），Consumer（消费者）用 `super`（只写）。

## 🐛 踩坑记录

- 泛型不能 new 泛型数组 / 泛型实例
- `static` 方法不能用类泛型，必须声明自己的 `<T>`
- 注解属性只能是基本类型、String、Class、枚举、注解或其数组
- 注解属性有默认值时使用可省略，但数组属性除外
- 类型擦除后数组创建受限：`new T[10]` ❌，可用反射
