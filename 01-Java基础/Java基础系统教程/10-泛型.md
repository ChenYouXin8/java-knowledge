# 第 10 章 泛型（Generic）

## 本章目标
- 理解泛型解决了什么问题（类型安全 + 免去强转）
- 会写泛型类、泛型方法、泛型接口
- 看懂通配符 `? extends / ? super`（PECS 原则）
- 理解类型擦除

---

## 10.1 为什么需要泛型

没有泛型时，集合只能存 Object，取出来要手动强转，类型错误要到运行时才暴露：

```java
// 没有泛型的旧写法（JDK 5 之前）
java.util.List list = new java.util.ArrayList();
list.add("hello");
Integer i = (Integer) list.get(0);  // 编译通过，运行时 ClassCastException！
```

泛型让你在**编译期**就约束类型，取出来不用强转，把运行时错误提前到编译期：

```java
java.util.List<String> list = new java.util.ArrayList<>();  // 只能放 String
list.add("hello");
String s = list.get(0);    // 不用强转
// list.add(123);          // 编译直接报错
```

一句话：**泛型 = 参数化的类型，把"类型"当成参数传进去，换来类型安全和代码复用。**

---

## 10.2 泛型类

在类名后加 `<类型参数>`，常用大写字母约定：`T`(Type)、`E`(Element)、`K`(Key)、`V`(Value)。

```java
// 一个能装任意类型的"盒子"
public class Box<T> {
    private T data;

    public void set(T data) { this.data = data; }
    public T get() { return data; }
}

Box<String> b1 = new Box<>();   b1.set("你好");
Box<Integer> b2 = new Box<>();  b2.set(100);
```

多类型参数：`class Pair<K, V> { K key; V value; }`。

---

## 10.3 泛型方法

泛型定义在方法上（与类是否泛型无关），`<T>` 写在返回值之前：

```java
public class ArrayUtil {
    // 泛型方法：交换数组两个位置
    public static <T> void swap(T[] arr, int i, int j) {
        T tmp = arr[i]; arr[i] = arr[j]; arr[j] = tmp;
    }

    // 泛型方法返回 T
    public static <T> T getFirst(java.util.List<T> list) {
        return list.get(0);
    }
}
String[] arr = {"a", "b"};
ArrayUtil.swap(arr, 0, 1);   // 编译器自动推断 T = String
```

## 10.4 泛型接口

```java
public interface Repository<T> {
    void save(T entity);
    T findById(long id);
}

// 实现方式一：实现时定死类型
class UserRepository implements Repository<User> {
    public void save(User u) { }
    public User findById(long id) { return null; }
}

// 实现方式二：实现类也保留泛型
class BaseRepository<T> implements Repository<T> {
    public void save(T e) { }
    public T findById(long id) { return null; }
}
```

## 10.5 类型通配符 `?` 与上下界（难点，面试常考）

`?` 表示"某种未知类型"，主要用在方法参数上，让方法更灵活。

### 上界 `? extends T`：只能读，不能写（生产者）
```java
// 接收 List<Integer>、List<Double>（都是 Number 的子类）
double sum(java.util.List<? extends Number> list) {
    double s = 0;
    for (Number n : list) s += n.doubleValue();  // 读出来当 Number，安全
    // list.add(Integer.valueOf(1));  // 编译错误：不知道具体是哪种子类，禁止写
    return s;
}
```

### 下界 `? super T`：可以写 T，读取只能当 Object（消费者）
```java
void addNumbers(java.util.List<? super Integer> list) {
    list.add(1); list.add(2);   // 能安全写入 Integer
    Object o = list.get(0);     // 读出来只能当 Object
}
```

### PECS 原则（记忆口诀）
> **Producer extends, Consumer super**
> - 要从集合里**读（产出）**数据 → `? extends T`
> - 要往集合里**写（消费）**数据 → `? super T`
> - 又读又写 → 不用通配符，直接 `List<T>`。

## 10.6 类型擦除（泛型的底层原理，必考）

Java 的泛型是**伪泛型**：只存在于编译期，编译后类型参数被"擦除"，运行时 `List<String>` 和 `List<Integer>` 都是同一个 `List`，里面都是 Object（有上界则擦除成上界类型）。

```java
List<String> a = new ArrayList<>();
List<Integer> b = new ArrayList<>();
System.out.println(a.getClass() == b.getClass());  // true！运行时都是 ArrayList.class
```

由此带来的限制（理解即可）：
- 不能 `new T()`、不能 `new T[ ]`（运行时不知道 T 是什么）。
- 不能用基本类型做类型参数（要用包装类，`List<int>` 非法，用 `List<Integer>`）。
- 静态字段/方法不能使用类的泛型参数（静态属于类，泛型属于实例化时的类型）。
- `instanceof` 不能带泛型参数。

---

## 10.7 工程实践与踩坑
- 集合一律声明泛型，杜绝裸类型 `List list = new ArrayList()`。
- 公共工具方法善用泛型，避免一堆重复的 Object 强转方法。
- 泛型只在编译期检查，反射、序列化场景要留意擦除导致的问题。
- 通配符别滥用，对外 API 参数用 `? extends/super` 提升灵活性，内部实现用确定类型。

---

## 本章小结
- 泛型把类型参数化，编译期保证类型安全、免去强转。
- 会写泛型类 `<T>`、泛型方法（`<T>` 在返回值前）、泛型接口。
- 通配符：读用 `? extends T`，写用 `? super T`（PECS）。
- 类型擦除：泛型只在编译期，运行时被擦除，故有诸多限制。
