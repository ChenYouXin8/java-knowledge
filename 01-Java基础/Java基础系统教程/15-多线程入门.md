# 第 15 章 多线程入门

## 本章目标

> 本章只做入门，建立正确概念；JUC、线程池、锁优化等深入内容在 `02-Java进阶/Java并发编程.md`。

## 15.1 进程与线程

- **进程**：一个正在运行的程序，拥有独立内存空间。
- **线程**：进程中的一条执行路径，一个进程可以有多个线程，它们**共享进程的堆和方法区**，但各有独立的程序计数器和虚拟机栈。
- **并发（concurrent）**：单核 CPU 快速切换，"同时"推进；**并行（parallel）**：多核真正同时执行。

为什么要多线程：提高 CPU 利用率、让界面/接口在耗时任务时不卡顿、提升吞吐。代价是带来线程安全、死锁、上下文切换开销等问题。

## 15.2 创建线程的 4 种方式

### ① 继承 Thread
```java
class MyThread extends Thread {
    @Override public void run() {
        System.out.println(Thread.currentThread().getName() + " 在执行");
    }
}
new MyThread().start();   // 调 start() 才会开新线程；直接调 run() 只是普通方法调用
```

### ② 实现 Runnable（推荐，解耦任务与线程，可多实现）
```java
Runnable task = () -> {
    System.out.println("任务执行中");
};
new Thread(task, "线程A").start();
```

### ③ 实现 Callable + FutureTask（能拿到返回值、能抛异常）
```java
import java.util.concurrent.*;
Callable<Integer> call = () -> {
    Thread.sleep(1000);
    return 42;
};
FutureTask<Integer> future = new FutureTask<>(call);
new Thread(future).start();
Integer result = future.get();   // 阻塞等待线程返回结果
```

### ④ 线程池（实际开发唯一推荐方式，见进阶）
```java
ExecutorService pool = Executors.newFixedThreadPool(3);
pool.submit(() -> System.out.println("线程池执行"));
pool.shutdown();
```
> 生产环境不要直接 `new Thread`（无法管理、开销大），用线程池；且阿里规范建议用 `ThreadPoolExecutor` 手动创建以明确参数。

Runnable 与 Callable 区别：Runnable 的 run 无返回值、不能抛受检异常；Callable 的 call 有返回值、可抛异常。

## 15.3 线程生命周期（六种状态，面试必考）

`Thread.State` 枚举：

```
NEW（new 出来，还没 start）
  │ start()
RUNNABLE（可运行：就绪 + 运行中）
  ├── 等锁 ──► BLOCKED（等待 synchronized 锁）
  ├── wait() ──► WAITING（无限等待，需 notify 唤醒）
  ├── sleep(t)/wait(t) ──► TIMED_WAITING（限时等待）
  └── 执行完 ──► TERMINATED（终止）
```

### 常用方法
| 方法 | 作用 |
|------|------|
| `start()` | 启动线程，JVM 自动调 run |
| `sleep(ms)` | 当前线程睡眠，**不释放锁**，时间到自动醒 |
| `join()` | 等待该线程执行完再继续（线程插队） |
| `setPriority(int)` | 优先级 1~10，只是"建议"，不保证 |
| `yield()` | 礼让，让出 CPU 但仍可能马上被调度 |
| `wait()/notify()` | Object 的方法，等待/唤醒，**会释放锁**，必须在 synchronized 中 |

> sleep vs wait：sleep 是 Thread 静态方法、不释放锁、时间到自动醒；wait 是 Object 方法、释放锁、要 notify 唤醒。

## 15.4 线程安全问题与 synchronized（入门）

多个线程同时修改**共享变量**，由于操作不是原子的，会出现结果错乱：

```java
class Counter {
    private int count = 0;
    public void add() { count++; }   // count++ 实际是"读-改-写"三步，并发会丢更新
}
```

`synchronized` 保证同一时刻只有一个线程执行被保护的代码（互斥 + 保证可见性）：

```java
class SafeCounter {
    private int count = 0;

    // 方式一：修饰实例方法，锁 this
    public synchronized void add() { count++; }
}

// 方式二：修饰代码块，锁指定对象（锁粒度更细，推荐）
public void add() {
    synchronized (this) {
        count++;
    }
}
```

- 同步方法锁对象：非静态锁 this，静态锁 `类.class`。
- 多个线程必须争**同一把锁**才有效。
- 入门先记住：**共享可变状态 + 多线程并发写 = 要加锁**。更优方案（Lock、CAS、并发容器、ThreadLocal）在进阶章节。

## 15.5 工程实践与踩坑
- 永远调 `start()` 开线程，别直接调 `run()`。
- 生产用线程池统一管理线程，不用时优雅 shutdown。
- 共享可变变量优先考虑不共享（局部变量）、不可变、或用并发工具，最后才手动加锁。
- 加锁范围尽量小，只锁真正访问共享数据的代码，避免把 IO、远程调用放进锁里。
- 死锁四条件、volatile、AQS、线程池 7 参数等深入内容，去 `02-Java进阶` 系统学。

## 本章小结
- 进程含多个线程，线程共享堆/方法区、私有栈和计数器。
- 4 种建线程方式：继承 Thread、实现 Runnable（推荐）、Callable 带返回值、线程池（生产推荐）。
- 六状态：NEW/RUNNABLE/BLOCKED/WAITING/TIMED_WAITING/TERMINATED；sleep 不放锁、wait 放锁。
- 并发改共享变量要用 synchronized（或更高级并发工具）保证安全。
