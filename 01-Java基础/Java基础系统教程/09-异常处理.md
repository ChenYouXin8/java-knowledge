# 第 9 章 异常处理

## 本章目标
- 理解异常体系（Error / Exception / 受检与非受检）
- 熟练 try-catch-finally、try-with-resources、throw/throws
- 会自定义业务异常
- 掌握异常处理的工程最佳实践

---

## 9.1 什么是异常

异常是程序运行时出现的非正常情况（如除零、空指针、数组越界、文件不存在）。Java 用"面向对象"的方式描述错误，并提供统一的捕获处理机制，避免程序直接崩溃。

异常体系：
```
Throwable（所有错误/异常的根）
├── Error：系统级严重错误，程序无能为力，如 OutOfMemoryError、StackOverflowError（不用捕获）
└── Exception：程序层面的异常
     ├── RuntimeException（非受检/运行时异常，编译器不强制处理）
     │    ├── NullPointerException 空指针
     │    ├── ArrayIndexOutOfBoundsException 下标越界
     │    ├── ClassCastException 类型转换
     │    ├── IllegalArgumentException 非法参数
     │    └── ArithmeticException 算术异常（如除零）
     └── 其他 Exception（受检/编译期异常，必须处理：捕获或声明抛出）
          ├── IOException、FileNotFoundException
          └── SQLException
```

**受检 vs 非受检（必考）**：
- 受检异常（checked）：编译器强制你 `try-catch` 或 `throws`，如 IOException。
- 非受检异常（unchecked）：RuntimeException 及其子类，编译不强制，多由代码逻辑 bug 引起，应靠写对代码避免。

## 9.2 五种处理方式

### ① try-catch-finally：捕获并处理
```java
try {
    int r = 10 / 0;                 // 这里抛 ArithmeticException
} catch (ArithmeticException e) {   // 精准捕获，先小后大
    System.out.println("算术错误: " + e.getMessage());
} catch (Exception e) {             // 父类异常放最后
    e.printStackTrace();
} finally {
    // 无论是否异常都会执行（除非 JVM 退出），常用于关资源
    System.out.println("一定会执行");
}
```
多个 catch 顺序：**子类异常在前、父类在后**，否则编译报错。JDK 7+ 可用 `catch (AException | BException e)` 合并。

### ② throws：声明方法可能抛出，交给调用者处理
```java
void readFile(String path) throws java.io.IOException {  // 声明受检异常
    // ...
}
```

### ③ throw：主动抛出一个异常对象
```java
if (age < 0) {
    throw new IllegalArgumentException("年龄不能为负: " + age);
}
```
> throw vs throws：throw 是**动作**（抛一个对象，在方法体内）；throws 是**声明**（方法签名上列出可能抛什么）。

### ④ try-with-resources（JDK 7+，推荐，自动关资源）
实现了 `AutoCloseable` 的资源（流、连接）写在 try 的括号里，结束后**自动关闭**，不用手写 finally：
```java
try (var reader = new java.io.BufferedReader(new java.io.FileReader("a.txt"))) {
    String line;
    while ((line = reader.readLine()) != null) System.out.println(line);
} catch (java.io.IOException e) {
    e.printStackTrace();
}   // reader 自动 close，即使发生异常也会关
```

### ⑤ finally 的执行细节（面试高频）
```java
int test() {
    try { return 1; }
    finally { System.out.println("finally"); }  // 会在 return 前执行
}
// 输出 finally，方法返回 1
```
finally 几乎总执行；若 finally 里也有 return，会覆盖 try 的返回值（不推荐这么写）。

## 9.3 自定义异常（项目必备）

业务中用自定义异常表达"业务规则不满足"，比返回错误码更清晰：

```java
// 自定义业务异常，通常继承 RuntimeException（非受检，用起来更顺手）
public class BizException extends RuntimeException {
    private int code;   // 可带业务错误码

    public BizException(int code, String message) {
        super(message);
        this.code = code;
    }
    public int getCode() { return code; }
}
```

```java
public void withdraw(double money) {
    if (money > balance) {
        throw new BizException(40001, "余额不足");
    }
    balance -= money;
}
```
Spring 项目里再配一个全局异常处理器（`@RestControllerAdvice`）统一把异常转成友好的 JSON 返回，这部分在 Spring 章节细讲。

## 9.4 工程实践与踩坑（Effective Java 风格）
- **不要吞异常**：`catch (Exception e) {}` 空块是大忌，至少打日志。
- 不要用异常做正常流程控制（异常创建开销大）。
- 捕获具体异常，别一上来 `catch (Exception e)` 一把梭。
- 异常信息要能定位问题（带关键参数），日志打印完整堆栈。
- 资源关闭优先 try-with-resources。
- 业务异常继承 RuntimeException，分层抛出、在最外层统一处理，不要层层重复 catch。
- `final / finally / finalize` 三者无关：final 修饰常量/类/方法，finally 是异常块，finalize 是已废弃的 GC 前回调（别用）。

---

## 本章小结
- Throwable 分 Error（不管）和 Exception；Exception 分受检（强制处理）和 RuntimeException（靠代码避免）。
- try-catch-finally 捕获、throws 声明、throw 抛出；资源用 try-with-resources 自动关。
- catch 先子类后父类；finally 总在 return 前执行。
- 自定义业务异常继承 RuntimeException，项目里统一抛出、统一处理。
