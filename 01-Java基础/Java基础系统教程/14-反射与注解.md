# 第 14 章 反射与注解

## 本章目标
- 理解 Class 对象与"运行时动态获取类信息"
- 会用反射创建对象、调方法、读字段
- 会自定义注解并通过反射读取
- 知道反射在 Spring 中扮演什么角色

> 反射是框架的灵魂：Spring 的 IoC、注解扫描、MyBatis 映射底层都靠它。基础阶段理解原理、会写小例子即可。

---

## 14.1 一切皆对象，类也是对象：Class

每个类被加载后，JVM 都会为它生成一个**唯一的 `Class` 对象**，里面记录了这个类的全部信息（字段、方法、构造器、注解等）。反射就是在**运行时**通过 Class 对象动态剖析和操作类。

获取 Class 对象的三种方式：
```java
// 1. 类名.class（编译期已知）
Class<User> c1 = User.class;
// 2. 对象.getClass()（运行期已有对象）
Class<?> c2 = new User().getClass();
// 3. Class.forName（全限定名字符串，框架最常用，最灵活）
Class<?> c3 = Class.forName("com.chen.demo.User");

System.out.println(c1 == c2 && c2 == c3);  // true：同一个类在 JVM 中只有一个 Class 对象
```

## 14.2 反射三大操作

假设有普通类：
```java
public class User {
    private String name = "默认";
    public User() {}
    public User(String name) { this.name = name; }
    public void sayHello() { System.out.println("你好，" + name); }
    private void secret() { System.out.println("私有方法"); }
}
```

### ① 创建对象
```java
Class<?> clazz = Class.forName("com.chen.demo.User");
User u1 = (User) clazz.getDeclaredConstructor().newInstance();   // 调无参构造

// 调有参构造
var ctor = clazz.getConstructor(String.class);
User u2 = (User) ctor.newInstance("张三");
```

### ② 调用方法（Method）
```java
Method m = clazz.getMethod("sayHello");      // 取 public 方法
m.invoke(u2);                                 // 你好，张三

Method secret = clazz.getDeclaredMethod("secret"); // 取私有方法要 getDeclared
secret.setAccessible(true);                  // 暴力破解权限，否则私有不可访问
secret.invoke(u2);
```

### ③ 读写字段（Field）
```java
Field f = clazz.getDeclaredField("name");
f.setAccessible(true);
System.out.println(f.get(u2));   // 读：张三
f.set(u2, "李四");               // 写
```

`getMethod/getField` 只能拿 public（含继承的）；`getDeclaredXxx` 拿本类声明的所有（含 private），访问私有要先 `setAccessible(true)`。

### 反射的优缺点
- 优点：运行期才确定类型，极其灵活，是框架实现解耦、配置化、插件化的基础。
- 缺点：比直接调用慢（破坏编译期优化）、破坏封装（能改私有）、编译期查不到错误。业务代码别滥用，框架层才用。

## 14.3 注解（Annotation）

注解是贴在类/方法/字段上的**元数据标签**，本身不改变代码逻辑，供编译器或框架（通过反射）读取处理。常见：`@Override`、`@Deprecated`、Spring 的 `@Controller`、`@Autowired`。

### JDK 内置元注解（修饰注解的注解）
- `@Target`：注解能贴在哪（TYPE 类、METHOD 方法、FIELD 字段、PARAMETER 参数…）
- `@Retention`：保留到什么时候
  - `SOURCE`（只在源码，编译丢弃，如 @Override）
  - `CLASS`（保留到 class，默认）
  - **`RUNTIME`（保留到运行时，可被反射读取，自定义框架注解都用它）**

### 自定义注解
```java
import java.lang.annotation.*;

@Target(ElementType.METHOD)
@Retention(RetentionPolicy.RUNTIME)   // 想运行时反射读取，必须 RUNTIME
public @interface MyLog {
    String value() default "";        // 注解属性，default 给默认值
    int level() default 1;
}
```

使用：
```java
class OrderService {
    @MyLog(value = "创建订单", level = 2)
    public void create() { System.out.println("下单"); }
}
```

### 用反射读取注解并处理（这就是框架做的事）
```java
Method method = OrderService.class.getMethod("create");
if (method.isAnnotationPresent(MyLog.class)) {
    MyLog log = method.getAnnotation(MyLog.class);
    System.out.println("记录日志：" + log.value() + "，级别 " + log.level());
    method.invoke(new OrderService());
}
```
Spring 扫描 `@Controller`/`@Service` 帮你创建对象、看到 `@Autowired` 帮你注入，本质就是启动时反射读取注解——理解了这个，就理解了 IoC 的一半。

## 14.4 工程实践与踩坑
- 反射创建对象优先用无参构造（很多框架要求 Bean 必须有无参构造，原因就在这）。
- 访问私有成员后 `setAccessible(true)`，模块化系统（JDK9+）下还可能需要开放模块权限。
- 自定义要被框架读取的注解，`@Retention` 一定设成 RUNTIME，否则反射读不到（新手最常见）。
- 反射性能敏感处可缓存 Method/Field 对象，避免每次重新获取。
- 业务层优先正常调用，反射只用于写通用框架/工具，别为炫技牺牲可读性。

---

## 本章小结
- 每个类运行时有唯一 Class 对象，三种方式获取，`Class.forName` 最灵活。
- 反射可动态 new 对象（Constructor）、调方法（Method）、读写字段（Field），私有要 setAccessible。
- 注解是元数据；自定义注解用 @Target/@Retention(RUNTIME)，通过反射读取处理。
- Spring 的 IoC/注解扫描底层就是反射 + 注解。
