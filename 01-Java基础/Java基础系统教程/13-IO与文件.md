# 第 13 章 IO 与文件

## 本章目标
- 分清字节流与字符流、节点流与处理流
- 会用现代 NIO（Files/Path）读写文件（推荐）
- 理解序列化与反序列化
- 知道什么场景用哪套 IO

> 老 IO 体系庞大，实际开发 90% 用 NIO 的 `Files` 工具类即可，本章重点放现代写法，老流理解原理、能看懂老代码。

---

## 13.1 IO 流分类全景

按数据单位分：
- **字节流**（8 位字节，处理一切文件，尤其图片/视频/压缩包）：`InputStream`/`OutputStream`
- **字符流**（16 位字符，只处理纯文本）：`Reader`/`Writer`

按角色分：
- 节点流：直接连数据源（如 `FileInputStream`）
- 处理流：包在别的流外面增强（如 `BufferedInputStream` 缓冲、`InputStreamReader` 转换）

命名规律：以 InputStream/OutputStream/Reader/Writer 结尾，前缀说明来源或功能（File、Buffered、Object、Print…）。

## 13.2 现代写法：NIO 的 Files（优先掌握，JDK 7+）

`java.nio.file.Files` + `Path` 提供大量静态方法，配合 try-with-resources，极其简洁：

```java
import java.nio.file.*;
import java.util.List;

Path path = Paths.get("data.txt");

// 一次性读取所有行（适合中小文本文件）
List<String> lines = Files.readAllLines(path);
lines.forEach(System.out::println);

// 一次性读取全部文本（JDK 11+）
String content = Files.readString(path);

// 写文本（覆盖 / 追加）
Files.writeString(path, "你好 Java");
Files.writeString(path, "追加一行\n",
        StandardOpenOption.CREATE, StandardOpenOption.APPEND);

// 逐行用 Stream 处理（大文件，避免一次性读进内存）
try (var stream = Files.lines(path)) {
    stream.filter(l -> l.contains("error")).forEach(System.out::println);
}

// 常用文件操作
Files.exists(path);                       // 是否存在
Files.createFile(Paths.get("new.txt"));   // 创建文件
Files.createDirectory(Paths.get("dir"));  // 创建目录
Files.copy(path, Paths.get("copy.txt"));  // 复制
Files.move(path, Paths.get("move.txt"));  // 移动/重命名
Files.deleteIfExists(path);               // 不存在不报错地删除
```

遍历目录：
```java
try (var walk = Files.walk(Paths.get("."))) {   // 递归遍历所有
    walk.filter(Files::isRegularFile).forEach(System.out::println);
}
Files.newDirectoryStream(Paths.get("."));       // 只列一层
```

## 13.3 经典字节流 / 字符流（看懂老代码、处理二进制）

### 字节流复制文件（最基础，一切文件通用）
```java
try (var in = Files.newInputStream(Paths.get("src.jpg"));
     var out = Files.newOutputStream(Paths.get("dst.jpg"))) {
    byte[] buffer = new byte[8192];   // 8KB 缓冲区
    int len;
    while ((len = in.read(buffer)) != -1) {  // read 返回读到的字节数，-1 表示到末尾
        out.write(buffer, 0, len);
    }
}
```

### 字符缓冲流逐行读写文本
```java
// 读
try (var reader = Files.newBufferedReader(Paths.get("a.txt"))) {
    String line;
    while ((line = reader.readLine()) != null) System.out.println(line);
}
// 写
try (var writer = Files.newBufferedWriter(Paths.get("b.txt"))) {
    writer.write("一行");
    writer.newLine();
}
```

> 经验：二进制（图片/音视频/任意文件）用字节流；纯文本用字符流（避免中文乱码）；**永远指定字符集 UTF-8**，别依赖系统默认。

## 13.4 序列化与反序列化

把内存中的对象转成字节序列存盘/传输叫序列化，还原叫反序列化。

```java
import java.io.*;

class User implements Serializable {       // 必须实现 Serializable 标记接口
    private static final long serialVersionUID = 1L;  // 版本号，强烈建议显式声明
    String name;
    transient String password;             // transient：不参与序列化（敏感/临时字段）
    public User(String name, String pwd) { this.name = name; this.password = pwd; }
}

// 序列化
try (var oos = new ObjectOutputStream(Files.newOutputStream(Paths.get("u.dat")))) {
    oos.writeObject(new User("chen", "123456"));
}
// 反序列化
try (var ois = new ObjectInputStream(Files.newInputStream(Paths.get("u.dat")))) {
    User u = (User) ois.readObject();      // password 为 null（被 transient 排除）
}
```

注意：被序列化对象的引用字段也必须可序列化；Java 原生序列化有安全和跨语言问题，**现代项目更多用 JSON（Jackson）传输对象**，原生序列化了解即可。

## 13.5 工程实践与踩坑
- 新项目读写文件优先 `Files` 工具类 + try-with-resources，不用手动 close。
- 读写文本显式指定 `StandardCharsets.UTF_8`，杜绝中文乱码。
- 大文件用 `Files.lines` 流式处理或带缓冲的分块读写，别 `readAllBytes` 一次性撑爆内存。
- 用完流务必关闭（try-with-resources 自动关），否则文件句柄泄漏。
- 对象传输优先 JSON；要用原生序列化就显式声明 serialVersionUID、敏感字段加 transient。

---

## 本章小结
- 字节流处理一切二进制，字符流处理文本；节点流连数据源，处理流做增强。
- 现代开发用 `Files`/`Path`：readAllLines、readString/writeString、lines、copy/move/delete。
- 复制文件用 8KB 缓冲字节流；文本用 BufferedReader/Writer，统一 UTF-8。
- 序列化实现 Serializable，transient 排除字段；实际项目优先 JSON。
