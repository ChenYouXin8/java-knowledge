# 第 6 章 继承与多态

## 本章目标
- 用 extends 实现继承，理解子类父类关系
- 分清重写（Override）与重载（Overload）
- 真正理解多态：向上转型、动态绑定，它解决了什么问题
- 掌握 super、final、Object 常用方法

---

## 6.1 继承：抽取共性，复用代码

当多个类有共同的字段和方法时，把共性抽到**父类（超类）**，子类用 `extends` 继承，自动拥有父类非 private 的成员。

```java
// 父类
public class Animal {
    protected String name;
    public void eat() { System.out.println(name + " 在吃东西"); }
}

// 子类继承父类
public class Cat extends Animal {
    public void climb() { System.out.println(name + " 会爬树"); }
}
```

```java
Cat c = new Cat();
c.name = "咪咪";
c.eat();    // 继承来的方法：咪咪 在吃东西
c.climb();  // 子类自己的方法
```

要点：
- Java **单继承**：一个类只能 `extends` 一个父类（但可以多层继承 A→B→C，也可实现多个接口，见第 7 章）。
- 子类拥有父类所有非 private 成员；`private` 成员被继承但不能直接访问。
- 继承是 "is-a" 关系：Cat **is an** Animal。不是 is-a 别硬继承（用组合，第 7 章）。
- 所有类的"老祖宗"都是 `java.lang.Object`。

## 6.2 super 关键字与构造器调用链

| 用法 | 含义 |
|------|------|
| `super.字段/方法()` | 访问父类的成员（常用于子类重写后仍想调父类版本） |
| `super(...)` | 调用父类构造器，**必须在子类构造器第一行** |

**子类构造器一定会先调用父类构造器**（默认隐式 `super()`），形成从 Object 往下的构造链：

```java
public Cat(String name) {
    super();        // 调用父类无参构造，不写也会自动加在第一行
    this.name = name;
}
```

> 踩坑：父类没有无参构造、子类又没显式 `super(参数)`，编译报错。

### 类初始化顺序（面试常考）
父类静态 → 子类静态（类加载一次）→ 父类实例块/构造 → 子类实例块/构造。静态只执行一次。

## 6.3 方法重写（Override）

子类对父类同名同参数方法给出**新的实现**，叫重写。规则（"两同两小一大"）：
- 方法名、参数列表必须**相同**；
- 返回值、抛出异常不能比父类**更大**（返回值可用子类类型，即协变）；
- 访问权限不能比父类**更严**（父 public，子类不能 protected）。

```java
public class Animal {
    public void sound() { System.out.println("动物发声"); }
}
public class Dog extends Animal {
    @Override   // 注解：让编译器帮你检查是否真的重写正确，强烈建议写
    public void sound() {
        super.sound();          // 可选：先执行父类逻辑
        System.out.println("汪汪");
    }
}
```

### 重写 Override vs 重载 Overload（必考对比）

| | 重写 Override | 重载 Overload |
|---|---|---|
| 发生位置 | 父子类之间 | 同一个类中 |
| 方法名 | 相同 | 相同 |
| 参数列表 | **必须相同** | **必须不同**（个数/类型/顺序） |
| 关系 | 运行时多态 | 编译时决定调哪个 |

## 6.4 多态：本章核心

**多态**：同一个父类引用，指向不同子类对象，调用同一个方法表现出不同行为。

前提三条件：**继承 / 实现、方法重写、父类引用指向子类对象（向上转型）**。

```java
Animal a1 = new Dog();   // 向上转型：父类引用 = 子类对象
Animal a2 = new Cat();
a1.sound();              // 运行时看实际对象 → 汪汪
a2.sound();              // → 喵喵
```

### 多态到底解决了什么问题？
没有多态时，每加一种动物，调用方都要写 if-else 判断类型；有了多态，**调用方只面向父类 Animal 编程，新增子类时调用方代码一行都不用改**——这就是"对扩展开放、对修改封闭"（开闭原则），也是 Spring 能面向接口注入的根本原理。

```java
// 统一面向父类，新增 Pig 也不用改这个方法
void letItSound(Animal a) { a.sound(); }
```

### 向上转型与向下转型
- 向上转型（自动、安全）：`Animal a = new Dog();`，但此时**只能调用父类中有的方法**，调不到 Dog 特有方法。
- 向下转型（要强转，有风险）：想调子类特有方法时，先判断类型：

```java
if (a instanceof Dog) {        // 先判断，避免 ClassCastException
    Dog d = (Dog) a;           // 向下转型
    d.guardHouse();
}
```
JDK 16+ 支持模式匹配，更简洁：`if (a instanceof Dog d) { d.guardHouse(); }`。

### 动态绑定
编译时看左边（父类）有没有该方法；运行时看右边（实际对象）执行谁的重写版本。成员变量不参与多态，看引用类型。

## 6.5 final 关键字三种用法

| 修饰 | 效果 |
|------|------|
| `final` 变量 | 常量，只能赋值一次 |
| `final` 方法 | 不能被子类重写 |
| `final` 类 | 不能被继承（如 String、Integer 都是 final 类） |

## 6.6 Object 类常用方法（所有类都有）

| 方法 | 作用 | 注意 |
|------|------|------|
| `toString()` | 返回对象字符串表示 | 默认打印地址，建议重写，IDEA 自动生成 |
| `equals(Object o)` | 比较内容是否相等 | 默认比地址，要比内容需重写（常和 hashCode 一起） |
| `hashCode()` | 返回哈希码 | 重写 equals 就必须重写它（集合章节解释） |
| `getClass()` | 返回运行时的真实类型 | |

```java
@Override
public String toString() {
    return "Dog{name='" + name + "'}";  // 打印对象时更友好
}
```

> 为什么重写 equals 必须重写 hashCode？因为 HashMap/HashSet 先按 hashCode 分桶再用 equals 比较，规则是"equals 相等的两个对象 hashCode 必须相等"，第 11 章细讲。

## 6.7 工程实践与踩坑
- 优先用组合（一个类持有另一个类）而非继承来复用，继承层次别超过 3 层。
- 重写方法一定加 `@Override`，拼错方法名时编译器能立刻发现。
- 面向抽象/父类编程：`List<User> list = new ArrayList<>();` 左边写接口，这就是多态思想。
- 向下转型前一定先 `instanceof`，否则可能 `ClassCastException`。

---

## 本章小结
- 继承用 extends，单继承，子类构造必先 super() 调父类构造。
- 重写在父子类、参数相同；重载在同类、参数不同。
- 多态 = 父类引用指向子类对象 + 重写，运行时动态绑定，支撑开闭原则。
- final 锁常量/方法/类；Object 的 toString、equals、hashCode 要会重写。
